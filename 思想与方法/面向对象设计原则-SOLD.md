# 单一职责原则（Single Responsibility Principle, SRP）

SOLID 里的 **S**，最简单、也最常用。

------

## 一句话核心

**一个类、一个方法，只负责一件事，并且只因为一个原因而修改。**

通俗说：

**不要把所有逻辑都塞到一个类 / 一个方法里。**

------

## 为什么要遵守？

- 代码**可读性高**：一看就知道这个类干嘛
- **易维护**：改一个功能，不影响其他功能
- **易复用**：小模块可以到处用
- **易测试**：逻辑简单，测试用例少



# 开闭原则（Open‑Closed Principle, OCP）

SOLID 里的 **O**，是**最核心、最顶层**的设计原则。

------

## 一句话记住

**对扩展开放，对修改关闭。**

- 要加新功能：**扩展代码**（新增类 / 方法）
- 不要：**修改原有已稳定的代码**

------

## 通俗解释

- 原来写好、测好、上线的代码，**不要再改它**。
- 新增需求，**新增代码**去实现，不碰老逻辑。
- 目的：**不改旧代码 = 不引入新 bug**。



# 里氏替换原则（Liskov Substitution Principle, LSP）

你想了解的里氏替换原则（简称 LSP）是 SOLID 五大设计原则中的第三个，核心是**子类必须能够替换掉父类，且不影响程序的正确性**，简单说就是 “子类可以扩展父类功能，但不能改变父类原有的行为”。

**通俗理解**：

- 父类能做的事，子类必须能做，且结果一致；
- 子类可以新增功能，但不能修改父类的核心逻辑；
- 用父类的地方，无脑换成子类，程序不能出问题。



# 接口隔离原则（Interface Segregation Principle, ISP）

SOLID 里的 **I**，就是**接口隔离原则**。

## 一句话核心

**客户端不应该被迫依赖它用不到的接口。**

—— 把大而全的接口，拆成多个**小而专一**的接口。

------

## 通俗理解

- 一个接口职责太多，就像**万能插座**，什么都能插，但谁用都觉得臃肿。
- 接口隔离就是：**拆成专用接口**，充电用充电口，听歌用耳机口，互不干扰。

# 依赖倒置原则（Dependency Inversion Principle，DIP）

SOLID 中的 **D**，就是**依赖倒置原则**。

------

## 一句话核心

1. **高层模块不依赖低层模块，二者都依赖抽象。**
2. **抽象不依赖细节，细节依赖抽象。**

## 为什么叫 “倒置”？

传统写法：

- 高层（业务） → 直接调用 → 低层（具体类）
- 依赖方向：**高层 → 低层**

依赖倒置后：

- 高层 → 依赖 → 抽象接口
- 低层 → 实现 → 抽象接口
- 依赖关系**倒过来**：都靠抽象连接。



# 组合 / 聚合复用原则（CARP）

也叫 **合成复用原则**，是设计模式里非常重要、但经常被忽略的一条原则。

- **继承 = 硬绑定父子关系**，耦合极强，牵一发动全身。
- **组合 = 把别人的功能拿来用**，我包含你，但我们不是父子，松耦合。



# 最少知识原则（迪米特法则 LoD）

也叫：**迪米特法则（Law of Demeter，LoD）**

核心思想：**一个对象应当对其他对象有尽可能少的了解。**

一个类的**直接朋友**只有这几种：

1. **当前对象本身（this）**
2. **方法入参里的对象**
3. **当前对象持有的成员变量对象**
4. **当前对象创建的对象**
5. **方法里的局部对象**
