# 架构设计

## 基本框架

Java 17、SpringBoot、SpringCloud

## 组件

Nacos：注册中心 + 配置中心

Spring Cloud Gateway：Nginx 做反向代理，网关负责微服务路由、鉴权、限流、请求转发，拆分前后端与服务流量。

**Spring Cloud OpenFeign**：微服务之间 RPC 调用，替代原生 RestTemplate，适配多模块（数据接入、评估、档案）跨服务交互。

**MyBatis-Plus:**业务库操作：指标体系、任务流程、故障规则、评估任务、档案目录等结构化数据 CRUD；MyBatis-Plus 自带分页、条件过滤，匹配你数据筛选、维度过滤功能。

**Spring Validation :**任务流程、文件配置、评估规则入参校验，对应文档里 “校验任务信息格式” 需求。

**Spring Task / @Async:**异步处理大文件分片解析、批量指标计算、报告生成，避免同步阻塞。

RocketMQ:实时消息队列监听、多源参试系统数据流归集、异步解耦评估计算

任务调度（评估批量计算、归档定时任务，可选刚需）:XXL-Job



## 工具类底层依赖

**Jackson（JsonNode）**

文档明确使用 JsonNode 做异构 JSON 反序列化、类型识别转化，SpringBoot 内置，建议锁定版本统一管理。

**SAX、Dom4j、XPath（XML 解析）**

文件解析模块需要 SAX 解析 XML 试验方案、Path 节点提取，配套工具处理配置 XML 与业务 XML 文件。

**docx4j + POI-TL + FreeChart**

文档评估报告生成模块指定技术栈：docx4j 无模板生成 Word、POI-TL 模板渲染、FreeChart 嵌入指标图表（折线 / 热力 / 甘特图），导出 Word/PDF 评估报告。

**Guava、Hutool**

通用工具：编码探测（UTF-8/GBK）、大文件分片、时间格式化（yyyy-MM-dd HH:mm:ss 时序对齐）、量纲单位转换、集合过滤（NaN / 空值剔除）。

**MapStruct**

DTO 与数据库实体快速转换，统一实时数据、文件解析输出的结构化数据模型。

XSS、CSRF 防护工具：

**Spring Cloud Alibaba Sentinel**

流量控制、熔断降级、系统负载保护；防止实时消息队列海量数据打垮评估服务，针对文件解析大文件并发限流。

**SkyWalking / Pinpoint（APM 链路追踪）**

全链路监控：实时数据接入→文件解析→数据筛选→指标评估→报告生成全链路调用耗时、异常捕获；定位解析卡顿、指标计算慢等问题。

**Spring WebSocket**

实时推送装备故障、试验异常、实时评估进度到前端监控大屏。

**Apache POI（补充）**

兼容 Excel 试验指标导入导出，拓展文件解析格式。

**Swagger3 / Knife4j**

API 在线文档，前后端联调、第三方系统对接（外部参试系统实时数据对接）。

**Lombok**

简化 Java 实体类 get/set，减少重复代码。

**规则引擎 Easy Rules / Drools**

文档有大量故障判断规则、评估过滤规则，使用规则引擎将业务判断逻辑与代码解耦，支持页面动态编辑故障判定规则，不用改代码重启服务。

## 数据存储分层

业务存在 4 类数据：结构化业务数据、海量时序指标、文件二进制、配置元数据

# 整体需求

1、实时数据接入解析

1）统一管理实时消息接入的数据源连接与规则映射，维护消息队列基于类型与来源作为联合主键的数据字段关系映射配置，支持配置的增删查改

2）对接入的参试各系统数据进行初步 JSON 解析后，确定数据来源与类型，根据对应的配置的映射规则进行解析转化

2、试验评估数据处理

基于任务所需的指标筛选所需要的指标参数，获取所有定义的指标体系参数，基于指标ID+指标名称的方式与全局指标体系做关联。进一步通过过滤规则，包括值过滤和维度过滤，筛选出能作为评估指标的数据

3、归一化

根据任务期间的数据在时间和量纲上进行对齐，包括量纲对齐和时序对齐

通过对带物理量指标进行预置规则转换实现量纲对齐2. 通过对时间格式转化为yyyy-MM-dd HH:mm:ss格式实现时序对齐

4、评估指标体系构建

构建多层次评估指标体系、设置评估方法，构建评估指标树，提供基于树的遍历算法和增删方法
